== Overview

The xref:index.adoc[CAM] workbench describes the item that cuts with four objects.
A xref:reference/glossary.adoc#tool-shape[Tool Shape] is a template.
A xref:reference/glossary.adoc#tool-bit[Tool Bit] is one item with its dimensions.
A xref:reference/glossary.adoc#tool-library[Tool Library] is a numbered list of Tool Bits.
A xref:reference/glossary.adoc#tool-controller[Tool Controller] (TC) connects one Tool Bit to the feeds and the Spindle Speed of a xref:reference/glossary.adoc#job[Job].

The CAM workbench stores each Tool Shape, each Tool Bit and each Tool Library as a file in the asset directory.
A TC is an object in the document of the Job.
This page gives the relation between these objects and links to each page of the section.

== Relation between the objects

* Tool Shape: a FreeCAD document (`.fcstd`) that gives the physical shape and the parameter names of a Tool Bit. Many Tool Bits can use one Tool Shape. For example, all Tool Bits of the `Endmill` type use the same Tool Shape file. See xref:tools/tool-shape.adoc[Tool Shape].
* Tool Bit: a JSON file (`.fctb`) that names one Tool Shape and holds the parameter values and the attributes. The file name is the ID of the Tool Bit. See xref:tools/toolbit.adoc[Tool Bit].
* Tool Library: a JSON file (`.fctl`) that gives a number to each Tool Bit ID. A Tool Library is independent of a Job. One Tool Bit can be a member of more than one Tool Library. See xref:tools/toolbit-library.adoc[Tool Library].
* Tool Controller: an object in the Tools group of a Job. A TC connects one Tool Bit to a *Tool Number*, a Spindle Speed, a spindle direction, the feeds and the rates of the rapid moves. See xref:tools/tool-controller.adoc[Tool Controller].

An xref:reference/glossary.adoc#operation[Operation] refers to a TC.
An Operation does not refer to a Tool Bit directly.
The Operation reads the Tool Bit of its TC to calculate the xref:reference/glossary.adoc#toolpath[Toolpath].

When you add a Tool Bit to a Job, the CAM workbench puts a copy of the Tool Bit into the document.
The TC owns this Tool Bit object.
The Tool Bit object keeps the ID of the library Tool Bit.
A change of the library Tool Bit does not change the Tool Bit object in the Job.
See <<update,Update from the Tool Library>>.

The figure shows the tree view of a Job with one TC in the Tools group and the Tool Bit object below the TC.

image::tools/index/relation.png["Tree view of a Job, with one Tool Controller in the Tools group and the Tool Bit object below the Tool Controller",400]

More than one TC of a Job can use the same Tool Bit with different feeds and speeds.
The number of a Tool Bit in a Tool Library is only the proposal for the *Tool Number* of a new TC.
See xref:tools/toolbit-library.adoc#tool-numbers[Tool numbers].

== Commands

Two commands of the menu:CAM[] menu give access to each Tool Bit and each Tool Library:

* image:CAM_ToolTable.svg[Add Toolbit…,16] xref:tools/add-toolbit.adoc[Add Toolbit…], menu:CAM[Add Toolbit…]: opens the _Toolbit Selector_ dialog. The dialog adds the selected Tool Bits to a Job as TCs.
* image:CAM_ToolTable.svg[Toolbit Library Manager,16] xref:tools/library-manager.adoc[Toolbit Library Manager], menu:CAM[Toolbit Library Manager]: opens the _Library Manager_ dialog. The dialog creates, changes, imports and exports Tool Bits and Tool Libraries.

== Work sequence

The usual sequence from a new Tool Bit to an Operation is:

. Select menu:CAM[Toolbit Library Manager].
. Select the Tool Library for the new Tool Bit, or select _All Toolbits_.
. Press btn:[Adds a toolbit]. The _Toolbit Shape Selection_ dialog lists the supplied Tool Shapes and your own Tool Shapes.
. Select a Tool Shape. The _Toolbit Parameter Editor_ dialog opens.
. Enter the values of the Tool Bit and press btn:[OK]. See xref:tools/toolbit.adoc[Tool Bit].
. Close the _Library Manager_ dialog.
. Select menu:CAM[Add Toolbit…].
. Select the Tool Bit and press btn:[Add to Job]. The CAM workbench creates a TC in the Job.
. Select the TC in the task panel of an Operation.

xref:tools/library-manager.adoc[Toolbit Library Manager] and xref:tools/add-toolbit.adoc[Add Toolbit…] describe the controls of the two dialogs.

== Asset directory

[.since]#introduced in 1.1#: The CAM workbench stores your Tool Bits, Tool Libraries and Tool Shapes in the CAM asset directory.
The default asset directory is `CamAssets` in the application data directory of FreeCAD.
menu:Edit[Preferences > CAM > Assets] sets the location of the asset directory.
See xref:reference/preferences.adoc[CAM Preferences].

The asset directory contains these folders:

* `Tools/Bit`: the Tool Bit files.
* `Tools/Library`: the Tool Library files.
* `Tools/Shape`: your own Tool Shapes.
* `Machines`: the Machine Templates (`.fcm`). menu:Edit[Preferences > CAM > Assets] adds and changes the Machine Templates. See xref:output/machine.adoc[Machine].
* `Templates`: the xref:reference/glossary.adoc#job-template[Job Templates].

FreeCAD supplies a set of Tool Bits, Tool Libraries and Tool Shapes in the folders `Bit`, `Library` and `Shape` of the installation directory.
The location of these folders is usually:

* Linux: `/usr/lib64/FreeCAD/Mod/CAM/Tools`
* Windows: `C:\Program Files\FreeCAD\Mod\CAM\Tools`
* macOS: `/Applications/FreeCAD.app/Contents/Resources/Mod/CAM/Tools`

The CAM workbench copies the supplied Tool Bits and the `Default` Tool Library into the asset directory.
See xref:tools/toolbit-library.adoc[Tool Library].
When the asset directory does not contain a Tool Shape, the CAM workbench uses the supplied Tool Shape in the installation directory.

The _Library Manager_ dialog writes each change to the asset directory immediately.
The _Library Manager_ dialog has no separate save step.

[.since]#introduced in 1.1#: When you activate the CAM workbench, the CAM workbench looks for a custom tool directory of an earlier version.
If the CAM workbench finds this directory, the _CAM Asset Migration_ dialog opens.
The _CAM Asset Migration_ dialog offers to copy each Tool Bit, each Tool Library and each Tool Shape into the asset directory.

When you open a document, the CAM workbench converts the Tool Bit property names `ShapeName` and `BitShape` to the current names.
The CAM workbench does not load a Job Template that uses the tool table of the versions before 0.19.

== Update from the Tool Library

[.since]#introduced in 26.3#: The CAM workbench compares the Tool Bits of a Job with the Tool Bits in the library.
The CAM workbench finds the library Tool Bit by the ID that the Tool Bit object of the Job keeps.
The comparison starts in two conditions:

* You open a document. The checkbox *Check for tool updates from the library when opening a document* in menu:Edit[Preferences > CAM > Assets] sets or stops this comparison.
* You select menu:Update Tools from Library[] in the context menu of the Job.

When a Tool Bit of a Job is different from the library Tool Bit, the _Tool Updates Available_ dialog opens.
btn:[Update] replaces each selected Tool Bit of the Job with the current library Tool Bit and recomputes the document.
btn:[Cancel] changes nothing.

xref:tools/toolbit.adoc[Tool Bit] describes the comparison and the _Tool Updates Available_ dialog.
xref:tools/tool-controller.adoc[Tool Controller] describes the effect of the update on the TC.

== Feeds and Speeds

[.since]#introduced in 26.3#: A Tool Bit can store xref:reference/glossary.adoc#preset[Presets].
A Preset holds a surface speed and a chipload for one material and one type of cut.
The Feeds and Speeds helper of the Tool Controller editor suggests the Spindle Speed and the feeds of a TC.
The helper uses the Presets, the material of the xref:reference/glossary.adoc#stock[Stock] and the spindle limits of the Machine.
See xref:tools/feeds-speeds.adoc[Feeds and Speeds].
