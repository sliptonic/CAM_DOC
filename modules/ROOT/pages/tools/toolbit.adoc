== Description

Toolbits are the foundation of the xref:tools/index.adoc[CAM Tools] system. They represent a specific tool that can be used in a CAM Job to generate a Toolpath. Each Tool Bit is stored as a JSON file. JSON is structured data that can be easily parsed by macros or python scripts but remains human readable. Describing Tool Bits with JSON allows for the possibility of automatically creating large collections of accurate Tool Bits with a script.

Storing a tool as a JSON file sounds great but eliminates the option of an accurate thumbnail or solid body representation. On the other hand, if each Tool Bit were created as a FreeCAD object, obtaining the solid body would be simple but would require enormous storage for large tool collections. Also automatically creating Tool Bits as FreeCAD objects would be difficult or impossible.

Instead, the Tool Bit is a hybrid. The JSON file names the xref:tools/tool-shape.adoc[Tool Shape] by its ID (for example `endmill.fcstd`, looked up in the `Tools/Shape` folder of the asset directory or the shipped shapes) and stores the values of the shape parameters and attributes.

When a Tool Bit is added to a Job, the Tool Shape body is copied into the document (hidden, property *BitBody*) and its solid is assigned to the Tool Bit object. Changing a parameter in the Shape group of the Tool Bit updates the solid after the next recompute. This provides the correct shape and dimensions which can be used to generate a point cloud or mesh for advanced algorithms (and potentially simulation).

== Usage

Within the FreeCAD GUI the Library Manager provides a mechanism to create a new Tool Bit. A single Tool Bit can exist in multiple Tool Libraries.

. Select menu:CAM[Toolbit Library Manager].
. Select a library (or _All Toolbits_).
. Press the btn:[Adds a toolbit] button and pick a Tool Shape in the _Toolbit Shape Selection_ dialog.
. In the _Toolbit Parameter Editor_ set the Label, Tool Number (only when a library is selected; the next free number is proposed), the Toolbit Type (editable only for shapes with subtypes, for example Drill: jobber, stub, spot, center, brad point), the shape parameters and the attributes, then press btn:[OK].
. To edit an existing Tool Bit, double-click it in the Library Manager or in the Toolbit Selector, or select it and press kbd:[F2].

To edit a Tool Bit that is in a document, see <<tool-bits-in-a-document,Tool Bits in a document>>.

=== Toolbit Parameter Editor

The _ToolBit editor_ (window title _Toolbit Parameter Editor_) has two tabs:

* _Toolbit_: Label, Toolbit Type, optional Tool Number, a Properties list (Shape and Attributes groups) with the abbreviations used in the shape drawing shown next to each parameter, and the shape drawing.
* _Feeds && Speeds_ [.since]#introduced in 26.3#: a table of the presets stored on the Tool Bit with btn:[Add preset], btn:[Edit], btn:[Copy] and btn:[Delete] buttons; see xref:tools/feeds-speeds.adoc[CAM FeedsSpeeds].

The figure shows the _Toolbit_ tab for the Tool Bit `5mm Endmill`.

image::tools/toolbit/editor-toolbit-tab.png["ToolBit editor on the Toolbit tab, with the properties and the shape drawing of an endmill",400]

A _Notes_ tab exists in the dialog definition but is hidden.

The Properties list does not show a calculated parameter, for example the *Diameter* of the Chamfer Tool Shape; see xref:tools/tool-shape.adoc[Tool Shape].

When the _ToolBit editor_ loads a Tool Bit, the _ToolBit editor_ sets the unit schema of FreeCAD to the *Units* of the Tool Bit. The _ToolBit editor_ sets the initial unit schema again when it closes.

The quantity fields of the _ToolBit editor_ show tool precision: 3 decimals when *Units* is `Metric` and 4 decimals when *Units* is `Imperial`. The Units Decimals preference does not change the number of decimals in these fields. When you change *Units* in the _ToolBit editor_, the _ToolBit editor_ builds the property fields again in the new units.

== Properties

.Base
* *ShapeID* (`String`, read-only): ID of the Tool Shape (`.fcstd`).
* *ShapeType* (`Enumeration`, read-only): the shape class (Endmill, Ballend, Bullnose, Chamfer, Drill, VBit, Dovetail, Reamer, SlittingSaw, Tap, ThreadMill, Probe, TaperedBallNose, Radius, Custom).
* *ToolBitID* (`String`, read-only): the unique ID of the Tool Bit (its file name in the library).
* *BitBody* (`Link`, hidden): the parametrized body.

.Shape
One property per parameter of the Tool Shape, for example *Diameter*, *Length*, *CuttingEdgeHeight*, *ShankDiameter*, *Flutes*. See xref:tools/tool-shape.adoc[CAM ToolShape] for the list per shape.

.Attributes
* *Units* (`Enumeration`: Metric, Imperial) [.since]#introduced in 26.3#: measurement units of the Tool Bit. The _ToolBit editor_ shows the quantity parameters in these units and FreeCAD saves them in these units. Default: `Metric`.
* *SpindleDirection* (`Enumeration`: Forward, Reverse, None): default spindle direction; copied to the Tool Controller when the Tool Bit is added to a Job. Probes never rotate.
* *Material* (`Enumeration`: HSS, Carbide): tool material; used by the Feeds and Speeds helper to pick the matching surface speed of the Stock material.
* *Chipload* (`Length`, cutting tools only): default chipload per tooth, used as a low-confidence fallback by the Feeds and Speeds helper.

.Feeds & Speeds
* *Presets* (`String`, only present once a preset was saved) [.since]#introduced in 26.3#: JSON list of Feeds & Speeds presets.

== JSON Structure

[.since]#introduced in 26.3#: the `parameter` object of a Tool Bit file can have the `Units` parameter with the value `Metric` or `Imperial`. Each Tool Bit file that FreeCAD supplies has the `Units` parameter. CAM calculations still use metric units internally.

FreeCAD saves each quantity parameter in the *Units* of the Tool Bit at tool precision: 3 decimals for `Metric` and 4 decimals for `Imperial`. The active unit schema and the Units Decimals preference do not change the saved text when *Units* is `Metric` or `Imperial`.

* FreeCAD saves a `Metric` value that it shows in µm with 4 decimals.
* FreeCAD saves an angle with the degree symbol directly after the number, without a space.

When a Tool Bit has no *Units* value, FreeCAD selects the unit and the number of decimals from the active unit schema. The Imperial schema gives 4 decimals. All other schemas give 3 decimals.

Tool precision applies to the values that FreeCAD saves. A Tool Bit file can have values with a different number of decimals, as the example shows.

The Camotics export does not use the *Units* property; see xref:tools/toolbit-library.adoc[Tool Library].

[source,json]
----
{
  "version": 2,
  "id": "5mm_Endmill",
  "name": "5mm Endmill",
  "shape": "endmill.fcstd",
  "shape-type": "Endmill",
  "parameter": {
    "Chipload": "0.0000 mm",
    "CuttingEdgeHeight": "30.0000 mm",
    "Diameter": "5.0000 mm",
    "Flutes": 2,
    "Length": "50.0000 mm",
    "Material": "HSS",
    "ShankDiameter": "3.0000 mm",
    "SpindleDirection": "Forward",
    "Units": "Metric"
  },
  "attribute": {},
  "presets": [
    {
      "name": "Aluminium profile",
      "material_hint": {"uuid": "…", "name": "Aluminium 6061"},
      "op_type_hint": "profile",
      "surface_speed": 300.0,
      "chipload": 0.05,
      "vert_feed_ratio": 0.33,
      "notes": null
    }
  ]
}
----

The keys are:

* `version`: always 2.
* `id`: the Tool Bit ID (optional; defaults to the file name).
* `name`: the label shown in the UI.
* `shape`: Tool Shape ID plus `.fcstd`.
* `shape-type`: the shape class or subtype (for example `Drill` or `jobber`).
* `parameter`: shape parameters and attributes as quantity strings.
* `attribute`: reserved, empty.
* `presets` [.since]#introduced in 26.3#: optional list of Feeds & Speeds presets (`surface_speed` in m/min, `chipload` in mm per tooth).

Unknown top-level keys are preserved when the file is re-saved.

== Tool Bits in a document

In a Job the Tool Bit object is shown as a child of its xref:tools/tool-controller.adoc[Tool Controller] and is hidden by default. Each Tool Controller has its own Tool Bit object.

Double-click a Tool Bit in the https://wiki.freecad.org/Tree_view[tree view] to open the _ToolBit editor_ as a https://wiki.freecad.org/Task_panel[task panel]. The task panel shows the *Label*, the *Toolbit Type*, the Properties list and the shape drawing of the Tool Bit. The task panel does not have the _Feeds && Speeds_ tab. btn:[OK] saves the Tool Bit and recomputes the document. btn:[Cancel] discards all edits that you made in the task panel.

The figure shows the task panel for the Tool Bit of a new Job.

image::tools/toolbit/editor-task-panel.png["ToolBit editor as a task panel, with the properties and the shape drawing of the Tool Bit",600]

The menu:Transform[] entry of the tree-view context menu starts the standard Transform manipulator of FreeCAD for the Tool Bit. The menu:Transform[] entry does not open the _ToolBit editor_. The tree-view context menu of a Tool Bit has no CAM entry of its own.

The commands `CAM_ToolBitCreate` (_New Toolbit_) and `CAM_ToolBitLoad` (_Load Tool_) exist but are not placed in any menu.

== Update from library

[.since]#introduced in 26.3#: an embedded Tool Bit is the copy of a library Tool Bit that a Job has in the document. A change of the library Tool Bit does not change the embedded Tool Bit. An update from the library replaces a stale embedded Tool Bit with a new copy of its library Tool Bit.

FreeCAD finds the library Tool Bit of an embedded Tool Bit only by the *ToolBitID* property. An embedded Tool Bit is stale when one of these conditions applies:

* The Feeds & Speeds presets of the embedded Tool Bit are different from the presets of the library Tool Bit.
* A property of the Shape group that is on the two Tool Bits has a different value.

FreeCAD does not compare the Shape group when the *ShapeType* of the two Tool Bits is different. FreeCAD does not compare a property that is on only one of the two Tool Bits. An embedded Tool Bit without a *ToolBitID*, or with a *ToolBitID* that is not in the local library store, is not examined and is not changed.

FreeCAD examines the embedded Tool Bits at two times:

* At document load. When a document becomes active for the first time after you open it, FreeCAD examines all Jobs of the document. The check occurs one time for each load of the document, after restore and recompute are complete. The check occurs only when the preference *Check for tool updates from the library when opening a document* in menu:Edit[Preferences > CAM > Assets] is set; see xref:reference/preferences.adoc[CAM Preferences].
* On request. The entry menu:Update Tools from Library[] in the tree-view context menu of a Job examines only that Job. The entry operates also when the preference is not set. When the Job has no stale Tool Bit, FreeCAD shows the message "This job has no tool updates available."

When a minimum of one embedded Tool Bit is stale, FreeCAD shows the _Tool Updates Available_ dialog. The table of the dialog has one row for each stale Tool Bit, in the sequence of the Job label and then of *Tool #*. The table has these columns:

* Checkbox column: selects the Tool Bit for the update. Each row is set by default. The checkbox in the table header sets or clears all rows and shows a partial state when only some rows are set.
* *Job*: the label of the Job.
* *Tool #*: *Tool Number* of the Tool Controller.
* *Tool*: the label of the embedded Tool Bit.
* *Changes*: the summary `Presets`, `Geometry` or `Presets, Geometry`.

When a Tool Bit has geometry changes, you can expand its *Changes* cell. The expanded cell shows one line `Presets` if the presets are different. The expanded cell shows one line for each changed property, with the property label, the value in the document and the value in the library. The dialog shows the two values in the *Units* of the library Tool Bit. The dialog does not show the presets item by item.

The figure shows the dialog with two stale Tool Bits and the *Changes* cell of the first row expanded.

image::tools/toolbit/tool-updates-available.png["Tool Updates Available dialog with two rows, and the Changes cell of the first row expanded",400]

btn:[Update] replaces only the Tool Bits of the rows that are set. btn:[Update] is disabled when no row is set. btn:[Cancel] changes nothing and is the default button.

An update always replaces the full Tool Bit. FreeCAD attaches a new full copy of the library Tool Bit to the document, with its presets, its Shape group values and its *Units*. FreeCAD then sets the *Tool* property of the Tool Controller to the new copy and removes the old Tool Bit object from the document. An update of only the presets or only the geometry is not possible. For the Tool Controller after an update, see xref:tools/tool-controller.adoc[Tool Controller].

CAUTION: Do not update an embedded Tool Bit whose local edits are necessary. The update removes the old Tool Bit object with all its local edits: presets, dimensions and other properties.

FreeCAD does not write a change of the *Presets* property of an embedded Tool Bit to the library Tool Bit; see xref:tools/feeds-speeds.adoc[Feeds & Speeds presets]. Thus an update from the library replaces the changed presets with the presets of the library Tool Bit.

After the update, FreeCAD hides each new Tool Bit in the 3D view and recomputes the document one time. FreeCAD does not replace a Tool Bit whose library Tool Bit was deleted after the check.

== Scripting

[source,python]
----
from Path.Tool.toolbit import ToolBit

tb = ToolBit.from_shape_id("endmill.fcstd", label="6mm Endmill")
tb.set_property("Diameter", "6 mm")
obj = tb.attach_to_doc(App.ActiveDocument)

# load from file
tb2 = ToolBit.from_file("/path/to/5mm_Endmill.fctb")

# library store access
from Path.Tool.camassets import cam_assets
tb3 = cam_assets.get("toolbit://5mm_Endmill")
----

The legacy module `PathScripts.PathToolBit` is no longer available.
